## What we are building

SafeSight is an AI tutor for Indian colleges that coaches students instead of doing their work, and shows teachers how their class uses AI. Core idea: **guide, don't guard.**

- **Sage** — student tutor. Hint ladder, never gives the final answer to graded work in Learn mode. (PLAN.md §4)
- **Lens** — teacher assistant. Plain-English questions about the class, read-only tools, answers with tables and small charts. (PLAN.md §4)
- **Trace** — Tiptap writing editor that records typing/paste/time; teacher replay; neutral evidence summary. (PLAN.md §4)
- **Live Lab Mode** — Chrome extension for lab exams on college PCs, live seat grid. Built after the core (S13–S15).
- **Landing site** — marketing page with pilot form. Design is finished; see `design/`.

## Non-negotiable rules

**Security**
- API keys only in server-side env vars. The browser never calls the model. No `NEXT_PUBLIC_` prefix on secrets.
- Row-level security on every Supabase table. Keep the test proving a student cannot read another student's messages.
- Lens tools are read-only and scoped to the teacher's own courses. No agent writes raw SQL.
- Rate limit Sage at ~60 messages per student per hour.
- Commit `.env.example`, never `.env*` with real values.

**Product voice**
- Never use the words "cheating", "cheater", "catch", "spy" or "AI-generated" anywhere in UI, prompts or copy. Trace reports evidence; teachers decide.
- Encouraging and plain: "Let's work through this together", not "Request denied".
- Students can see all of their own data. Teachers see summaries by default.
- Student data is never used to train models.
- Demo and seed data use invented Indian names only (e.g. Riya Sharma, Arjun Mehta, Sneha Iyer).
- Never invent statistics on the marketing site. Survey numbers stay as `[XX]%` placeholders until real results exist.

**Design**
- Use the exact tokens in `design/tokens.json` (also PLAN.md §5). Light and dark mode from day one, following system setting.
- Instrument Serif for large headlines only; Geist for UI and body (16px / 1.6); Geist Mono for numbers and code.
- 8px grid, 12 columns, 1200px max content width, 16px card radius, 1px borders instead of heavy shadows.
- Amber accent only for the single most important highlight on a screen.
- Lucide icons at 1.5px stroke. No eye icons, padlocks, robots or purple-blue gradients.
- Motion: 150–600ms, ease-out, animate only opacity/position/scale, respect `prefers-reduced-motion`.
- Mobile-first: Sage chat and Trace editor must work at 375px.
- Touch targets ≥ 44px, visible focus states, WCAG AA contrast in both themes.
- No lorem ipsum. Designed empty states and loading skeletons.

- **S16 (Sage safety and speed)** shipped from `claude/great-bohr-o1sjsj`. The policy is in code, not only in the prompt. Decisions made without asking:
  - **Pipeline** (`lib/sage/engine.ts`, used by `/api/sage` and `pnpm eval:sage`): `planTurn` runs `classifyMessage` and the notes search **in parallel** (notes are now prefetched with the student's message as the query and put in the prompt; the model-called `search_course_material` tool is gone, which saves a model round-trip) → `decidePolicy` → prompt with explicit ALLOWED/FORBIDDEN lists → `writeReply` → guard. Exam chats skip the classifier model (keyword labels only, no model call at all for the fixed reply).
  - **Labels** (`labels.ts`): intents `concept, answer_seeking, verify_answer, attempt, deliverable_request, jailbreak, distress, off_topic`, plus `attemptQuality` 0–1, `sharesWorking`, `claimsPermission`, distress, topic, and `match {assignmentId, similarity}`. In the DB `concept` is stored as the old `concept_question`; `pasted_question` is legacy (read as answer_seeking). The keyword net can force distress > jailbreak > deliverable_request > answer_seeking > verify_answer over the model and caps attempt quality on insist/deliverable messages. **Matching** (`match.ts`): the classifier sees the student's *active* assignments in the course (due within the last 14 days or later, or no due date) as refs A1…; `bestMatch` takes the higher of its score and a lexical one (shared words, the problem's own numbers, 5-word verbatim runs, or naming the assignment's title — "set 3" ≠ "set 2"). Threshold `MATCH_THRESHOLD = 0.55`.
  - **Policy engine** (`policy.ts`, tested): governing assignment = the chat's own one for every intent except a general concept/off-topic question (those only if they match its content); in Explore, a matched assignment; when two apply, the stricter mode wins (exam > learn > assist); an Exam chat governs everything. Reply kinds: `care` (distress, first), `exam_off` and `jailbreak` (fixed replies, no model call), `explain` (no assignment: free, streamed), `concept` (Learn: explain generally, don't apply to the task), `ladder` (Learn hint), `check_work` (shared working with quality ≥ 0.5 → step 5: say what's right, point at the first wrong step), `ask_working` (bare answer to verify → no verdict, ask for working), `assist` (Assist, and *any* deliverable request even in Explore: explain fully, never the deliverable). **Ladder state** lives in `sage_ladder_state` per student per assignment: Learn starts at 1, Assist at 3; it climbs one step only when `attemptQuality ≥ 0.5` on a non-insisting message, never on repetition, insistence, permission claims or a new chat; capped by the teacher's `max_hint_level` (1–4) and at 3 when worked examples are off. Step 4 gives a fresh parallel example at most once per assignment per hour (`last_example_at`); essays get bullet-fragment structure notes, never prose; examples must change the scenario *and* the unknown.
  - **Output guard**: `guard.ts` (deterministic, every draft and every streamed sentence): values from any active answer key that the student hasn't seen (±0.6%, so rounding doesn't slip through), 6-word overlap with an answer key or teacher notes, 8-word overlap with the system prompt (or the `SAGE-POLICY` marker), verdict words on a bare answer, essay-like prose (2 paragraphs ≥ 60 words, one ≥ 110, or ≥ 380 words) and code (≥ 12 lines, or defining the function the code assignment asks for — that one in any chat). `guard-model.ts` is the second, cheap model call (structured JSON, 6 s). Governed replies (`guard: "full"`) are **held until checked** and then sent at once; free explanations (`"light"`) **stream sentence by sentence**, never emitting inside an open ``` or $$ block. A failed draft is regenerated once with the rejection reason and stricter rules (only if ≥ 18 s remain); a second failure sends `safeHint()`. If the guard model is unavailable, a governed draft goes out only if it has no new numbers and no code. Outcome per reply in `messages.guard` (`pass/regenerated/safe_hint/fixed`). Distress replies never fail: a fixed `careReply()` if the model errors.
  - **Speed**: auth + body, then one parallel batch (chat/course under RLS, rate limit, idempotency lookup), then a second (ownership, active assignments with secrets, history, recent activity, open flags, materials, ladder). The conversation and the student's message are inserted in the background (`after()`); labels, flags, ladder state and the weekly-metrics refresh run after the plan; the reply is saved after the stream (the stream's `finish` waits only for the conversation insert so the next message can't race it). Timeouts: classify 4 s (`SAGE_CLASSIFY_MS`, falls back to keywords), notes 2.5 s, draft 25 s (`SAGE_DRAFT_MS`), guard 6 s (`SAGE_GUARD_MS`); `maxDuration = 60`, internal deadline 55 s. **Every chat-model call now gets one retry** (`lib/ai/provider.ts`): if the main model fails or hasn't started within `AI_SLOW_MS` (default 10 s, 5 s in demo mode) it is cancelled and retried on `AI_FALLBACK_MODEL`, or on the main model when unset; `DEMO_MODE` only adds the 5-minute stickiness. Each turn logs one JSON line `{"event":"sage_turn", ttftMs, latencyMs, classifyMs, searchMs, draftMs, guardMs, guard, kind, …}` and saves `ttft_ms`/`latency_ms` on the reply.
